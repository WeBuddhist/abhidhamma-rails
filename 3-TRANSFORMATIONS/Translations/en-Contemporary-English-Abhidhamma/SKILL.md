# zero-shot-keyword-glossary

Produces a **first-pass draft glossary** that fills the gaps in a track's `termbase.md` before any reference translation is consulted. For every keyword in the track's keyword list, the Cursor agent emits **exactly one** target-language rendering, drawing only on (a) its own knowledge of the source language and (b) the source-only example contexts harvested from the root text. The output is explicitly marked `status: draft` and is never promoted directly to the rails — it is the seed input for the next pass through `glossary-select`.

This skill is the answer to a recurring failure mode: when a translation track's `termbase.md` has hundreds of `<TODO>` rows, drafters either stall waiting for a Pāli reviewer or silently borrow renderings from a 1900-era reference translation (e.g. Rhys Davids) whose register clashes with the track's `requirements.md`. The zero-shot draft gives every term a register-correct candidate immediately, so reviewers can promote, reject, or refine — never start from blank.

---

## Inputs

- **Track folder** — `3-TRANSFORMATIONS/Translations/<track-name>/`. Must already contain:
  - `requirements.md` — defines translation philosophy, locked Pāli terms, locked English renderings, register constraints.
  - `audience.md` — defines reading level, vocabulary register, idiom region.
  - `termbase.md` (optional) — existing per-track termbase; rows the agent may not override.
- **Keyword list** — `pi-keywords.txt` (or `<source>-keywords.txt`). One lemma per line, ranked by document frequency. Generated upstream by `extract_pali_keywords.py`.
- **Source-only context file** — `pi-keywords-context.md` (or `<source>-keywords-context.md`). Pāli-only example blocks, one section per keyword, generated by `gather_examples.py` with **no English** parallel text.

The skill **must not** read:

- Any file under `1-SOURCES/Translations/` (these are reference translations and would contaminate the zero-shot).
- Any consolidated bilingual glossary at `2-RAILS/Bilingual-Glossaries/<pair>.md` (this skill produces a draft for the *track*; consolidation happens later via `glossary-combine` / `glossary-select`).

If any input is missing, stop and ask the human contributor — do not improvise.

---

## Output

One file at:

```
3-TRANSFORMATIONS/Translations/<track-name>/pi-en-zero-shot.md
```

(replace `pi-en` with the track's actual `<source>-<target>` pair).

Frontmatter records the inputs consulted, the inputs deliberately *not* consulted, the keyword count, the timestamp, the method, and `status: draft`.

The body has three sections in this exact order: a **Style contract** (a 4–6 bullet summary of the constraints distilled from `requirements.md` and `audience.md`), a `<!-- compact -->` marker, and the **compact form** itself — one bullet per keyword, in the same rank order as the input keyword list.

```markdown
# <Source> to <Target> zero-shot glossary (Cursor-native)

One <target-language> rendering per <source-language> keyword, generated
by the Cursor agent from the lemma plus the source-only example
contexts. No external API and no reference translation are consulted.

## Style contract

- **Reading level:** <from audience.md §2.>
- **One rendering per keyword.** Sense splits go in `termbase.md`, not here.
- **Locked source-language terms (kept untranslated):** <list from requirements.md §1.3>
- **Locked target-language renderings:** <list of must-be-distinct pairs from requirements.md §1.4>

> Status: AI-authored zero-shot, `draft`. Cross-check with primary
> dictionaries and the consolidated rails glossary before promoting any
> row to `partial` or `complete`.

---

## Compact form

<!-- compact -->

### <Group heading 1> (1–50)

1. **<keyword>**: <one rendering>
2. **<keyword>**: <one rendering>
…

### <Group heading 2> (51–100)
…
```

The bullet form is fixed:

- `<rank>. **<source-keyword>**: <one English rendering>`
- No parentheses, no semicolons, no numbered senses (`(1) … (2) …`). The skill emits *exactly one* rendering. If a keyword has multiple corpus senses, the skill flags the row with a trailing `— [sense-split: see termbase.md]` and picks the dominant sense for the rendering itself.
- Sandhi fragments and inflected non-lemmas are still rendered, but with a parenthetical structural note, e.g. `45. **nibbānañca**: and *Nibbāna* (sandhi *nibbānaṃ + ca*)`.
- Locked Pāli terms appear as Pāli, italicised, e.g. `44. **kamma**: *kamma*`.

---

## Rules

1. **One rendering per keyword.** No `(1) X; (2) Y` lists. If two senses are genuinely distinct, the skill picks the one most attested in the source-only contexts and tags the row for follow-up; the second sense becomes a `<TODO>` in `termbase.md`, not a parallel gloss here.
2. **No reference-translation contamination.** The agent must not read any file under `1-SOURCES/Translations/` while producing this output. If the human contributor wants a reference-translation-aware glossary, that is a different skill (`glossary-select`).
3. **Style contract is binding.** Every rendering must pass the `requirements.md` register test (e.g. *let go of* not *relinquish* if the audience is 6th-grade) and the `audience.md` reading-level test. Renderings that read above the calibrated level are rejected and re-drafted.
4. **Locked terms are sacrosanct.** Anything `requirements.md §1.3` (or equivalent) marks as kept-in-source-language stays in the source language and is italicised on first occurrence.
5. **Locked target distinctions are preserved.** If `requirements.md` locks a synonym set (e.g. *saññā* = perception, *viññāṇa* = consciousness, *paññā* = wisdom), each lemma in that set gets its locked rendering — never a swap, never a hyphenated combination.
6. **Source rank order preserved.** Bullets follow the same rank order as the input keyword list. The agent may add `### <Group heading>` subheadings every 50 entries for navigation, but the underlying numbering does not change.
7. **Coverage is total.** Every keyword in the input list gets a rendering. There are no skipped rows. Sandhi fragments, inflected forms, and obscure compounds all receive a rendering — with a structural note where the morphology, not the meaning, is the point.
8. **Frontmatter is honest.** The `sources_consulted` and `sources_NOT_consulted` lists are literally true — they are checked by the readability reviewer at the next gate.

---

## Procedure

1. **Read `requirements.md`** in full. Extract the locked source-language terms, the locked target-language renderings, the register constraint, the audience-level constraint, and the explicit "what we never do" list (§1.4 in the en-Contemporary-English-Abhidhamma instance).
2. **Read `audience.md`** in full. Note the target reading grade, the regional idiom constraint, the vocabulary preference (everyday word vs. elevated word).
3. **Read the existing `termbase.md`** if it exists. Any row whose `Origin` is not `TODO` is a locked rendering — copy it into the zero-shot output verbatim. Only `TODO` rows are filled by this skill.
4. **Read the keyword list** (`pi-keywords.txt`). Treat the line order as the rank order to preserve.
5. **Read the source-only context file** (`pi-keywords-context.md`) once. For every keyword the file shows up to two example blocks in the source language alone. The agent uses these to disambiguate which sense to render when a lemma is polysemous; the agent does **not** use them as a translation crib (they are not translated).
6. **Draft the file header and style contract** from steps 1–2. The style contract is short — 4–6 bullets — and is pasted into the output verbatim so a reviewer can check at a glance whether the rest of the file complies.
7. **Draft the compact form**, in batches of 50 keywords per `### <Group heading>`. Each entry is one line, one rendering. Apply the style contract on every entry.
8. **Self-check on locked terms.** Grep the draft for the locked source-language terms (e.g. `*Nibbāna*`, `*Buddha*`, `*Dhamma*`, `*Saṅgha*`, `*kamma*`, `*jhāna*`); confirm each one stays in the source language. Grep for the locked target-language renderings (e.g. `perception`, `consciousness`, `wisdom`); confirm each one is used for, and only for, the lemma it is locked to.
9. **Run the read-aloud test on a 5 % sample** (every 20th rendering). A fluent target-language reader should be able to read each sample line aloud at speaking pace without stumbling. Renderings that fail are redrafted.
10. **Write the output** to `3-TRANSFORMATIONS/Translations/<track-name>/<source>-<target>-zero-shot.md`. Set frontmatter `total_keywords` and `last_updated`. Set `status: draft`.

## Re-running this skill

The zero-shot file is regenerated whenever:

- `requirements.md` changes — register, locked terms, or audience-level constraints have shifted; previous renderings may no longer comply.
- `audience.md` changes — target reading grade or idiom region has shifted.
- The keyword list grows — `extract_pali_keywords.py` has produced a longer ranked list; new rows need first-pass renderings.
- A reviewer has flagged a batch of rows as register-noncompliant during the next gate (`glossary-select`); those rows are reset to zero-shot and redrafted.

In each case the existing zero-shot file is read first and any row whose `termbase.md` `Origin` is now `BB curated` / `BB in-text` / `derived` is preserved verbatim — only `TODO`-equivalent rows are redrafted.

## Helpers

Two scripts at the workspace root cooperate with this skill. The skill itself is read-only on these scripts; it invokes them but does not modify them.

- `extract_pali_keywords.py` — emits `pi-keywords.txt` and `pi-keywords.md`. Keyword selection is governed by document-frequency caps and a Pāli-stopword list.
- `gather_examples.py` — emits `pi-keywords-context.md`. **Pāli-only by design**: the script does not accept an `--english` argument and does not read any reference-translation file. This is the input invariant the skill relies on.

## Completion checklist

- [ ] Frontmatter fields `track`, `language_pair`, `requirements`, `audience` resolve to existing files.
- [ ] `sources_NOT_consulted` lists every reference translation in `1-SOURCES/Translations/` and the consolidated bilingual glossary at `2-RAILS/Bilingual-Glossaries/<pair>.md`.
- [ ] `total_keywords` matches the line count in the input keyword list.
- [ ] Every keyword in the input list has exactly one bullet in the output.
- [ ] No bullet contains the patterns `(1) `, `(2) `, ` ; ` (semicolon between glosses), or ` / ` (slash between glosses).
- [ ] Every locked source-language term stays in the source language and is italicised.
- [ ] Every locked target-language rendering is used for, and only for, its locked lemma.
- [ ] `status: draft`. The skill never sets `status: partial` or `status: complete` — those gates are reached only after `glossary-select` review.
