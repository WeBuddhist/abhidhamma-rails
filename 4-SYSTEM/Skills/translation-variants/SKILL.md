# translation-variants

This skill analyses a block-aligned source (Pāli) and target (English) markdown file pair and produces a YAML glossary showing every attested English rendering for each Pāli stem and how often each rendering occurs.  It is the descriptive counterpart to the prescriptive per-track termbase: where `termbase.md` records the *chosen* rendering, the variant table records *all* attested renderings so the human contributor can compare options and detect inconsistency.

The algorithm runs in two passes:

1. **TF-IDF keyword extraction (English).** Each block in the target file is treated as a document.  Tokens are scored by TF (block-document frequency within this translation) × IDF (inverse COCA corpus frequency via `en_freq.py`).  Domain-specific Buddhist terms score high; common English words are suppressed without appearing in an arbitrary stop-list.

2. **Sub-block Pāli alignment.** Each source/target block is split on `(Ka)/(Kha)/(Ga)` section markers before alignment, so that triad entries like `kusalā dhammā ↔ Wholesome states` are matched at the *line* level rather than the block level.  This prevents the three members of a triad from appearing as co-occurrences of each other.  For each English keyword the weighted Pāli co-occurrence is computed (weight = 1 / |unique Pāli stems in that sub-block|, so short mātikā entries outweigh long prose paragraphs).  The top-ranked Pāli stem(s) are stored.

## Output file format

```yaml
# Translation variant frequencies
# Method: English TF-IDF keyword extraction + sub-block Pali alignment
# pali_stem:
#   en_rendering: co_occurrence_count
#
# Generated by 4-SYSTEM/Skills/translation-variants/scripts/translation_variants.py

āsava:
  cankers: 7
  taints: 6
  influxes: 4

ogha:
  floods: 9

nīvaraṇa:
  hindrances: 15
  hindrance: 4
```

- `pali_stem` — the output of the light Pāli inflection stemmer (long case suffixes stripped; very long compound stems > 12 normalised characters are discarded).
- `en_rendering` — a domain-keyword token from the translation (common English words filtered by COCA reference).
- `co_occurrence_count` — raw number of (sub-)block pairs in which both appear.  Not a normalised frequency; use it for relative comparison only.

---

## Rules

1. **Never modify source files.** This skill reads `1-SOURCES/` and `3-TRANSFORMATIONS/` and writes only to the output path.
2. **Run from the vault root.** All paths in the command are relative to the vault root.
3. **Both files must have matching block IDs.** If the alignment count is zero, stop and report the mismatch to the human contributor.
4. **Output goes to `0-INBOX/` first.** Move it to `2-RAILS/Bilingual-Glossaries/Raw/` only after a human contributor has reviewed it for obvious errors.
5. **The variant table is descriptive, not prescriptive.** It records what the translation *did*, not what it *should* do.  Prescriptive choices belong in `termbase.md`.

## Procedure

### Step 1 — Identify inputs

Confirm both files exist and share block IDs.  A quick check:

```bash
grep -c '\^' 1-SOURCES/Text/pi-1.md
grep -c '\^' 3-TRANSFORMATIONS/Translations/en-Contemporary-English-Abhidhamma/en-dhammasangani-ai.md
```

Both counts should be identical (or very close).

### Step 2 — Run the extraction script

```bash
python3 4-SYSTEM/Skills/translation-variants/scripts/translation_variants.py \
    <source_file> \
    <target_file> \
    <output_yaml>
```

Example:

```bash
python3 4-SYSTEM/Skills/translation-variants/scripts/translation_variants.py \
    1-SOURCES/Text/pi-1.md \
    3-TRANSFORMATIONS/Translations/en-Contemporary-English-Abhidhamma/en-dhammasangani-ai.md \
    0-INBOX/translation-variants-pi-en.yaml
```

The script prints a summary:

```
source : ... (N blocks)
target : ... (N blocks)
aligned: N block pairs
terms  : N Pali stems in output
output : ...
```

If `wordfreq` is installed (`pip install wordfreq --break-system-packages`), it is used automatically for better IDF estimates; otherwise the bundled COCA approximation in `en_freq.py` is used.

### Step 3 — Review the output

Open the YAML and spot-check:

- Key terms (`āsava`, `ogha`, `nīvaraṇa`, `gantha`, `kusala`, etc.) should appear with their expected renderings.
- Renderings that look like noise (very common English words, obvious co-occurrences rather than translations) indicate that the source and target blocks may not be well-aligned, or that the text is very formulaic prose.

### Step 4 — Move to final location (if satisfactory)

```bash
cp 0-INBOX/translation-variants-pi-en.yaml \
   2-RAILS/Bilingual-Glossaries/Raw/pi-en-<track-short>-variants.yaml
```
